# VPN Control Panel

Своя панель управления VPN-серверами на замену Marzban: FastAPI + Postgres,
серверный рендеринг на Jinja, лёгкий агент на каждой ноде.

Главная особенность — **переход без потерь для пользователей**: панель
проверяет токены подписок тем же алгоритмом, что и Marzban, поэтому после
миграции все выданные ранее ссылки продолжают работать, а UUID и пароли
в конфигах остаются прежними. Боты и мобильное приложение тоже не требуют
правок: панель отвечает на те же запросы `/api/*`, что и Marzban.

## Что умеет

**Серверы**
- список нод: статус, версия Xray, CPU/RAM, аптайм, трафик;
- конфиг Xray генерируется панелью и заливается на ноды автоматически —
  на серверах ничего не правится руками;
- перезаливка только при реальном изменении (сравнение по хешу конфига);
- при недоступной ноде конфиг откатывается на прошлый рабочий, нода не ложится;
- ручные действия: синхронизировать, перезапустить, выключить, удалить.

**Пользователи и подписки**
- создание, продление, лимиты трафика, заморозка, удаление;
- автоматический перевод в `expired` / `limited` и возврат в `active`
  при продлении;
- отзыв подписки с перевыпуском ключей;
- учёт трафика по каждому пользователю и каждой ноде (почасовые срезы);
- ссылка подписки в форматах base64 (v2rayNG, Hiddify, NekoBox), plain и JSON.

**Журнал и уведомления**
- аудит всех действий — и из панели, и из ботов через API;
- уведомления в Telegram при падении и восстановлении ноды.

## Архитектура

```
                    ┌──────────────────────────────┐
   NexloVPN бот ───▶│                              │
   TGAdminBot   ───▶│   Панель (FastAPI+Postgres)  │──── агент ──▶ Xray  (нода 1)
   AppVPN       ───▶│   /api/*  /c/<token>  /веб   │──── агент ──▶ Xray  (нода 2)
                    └──────────────────────────────┘
```

- Панель — единственный источник правды: хранит пользователей, ключи и
  описание inbound'ов, из них собирает конфиг Xray для каждой ноды.
- Агент (`agent/agent.py`) ставится на VPN-сервер, принимает конфиг,
  супервизит процесс Xray и отдаёт статистику трафика. Отдельный systemd
  для самого Xray не нужен — им управляет агент.
- Учёт трафика: агент забирает счётчики из Xray API с обнулением, панель
  прибавляет дельту пользователю и складывает в часовые срезы.

```
app/
  core/        конфиг, БД, логирование, пароли и токены
  models/      admins, nodes, inbounds, hosts, users, user_proxies, usage, audit
  services/    генерация конфига Xray, ссылки, подписки, клиент к агенту,
               синхронизация нод, фоновые задачи, уведомления
  api/         Marzban-совместимый REST + выдача подписок
  web/         страницы панели
  templates/   Jinja-шаблоны
agent/         агент для ноды (ставится на VPN-сервер)
scripts/       установка агента, миграция из Marzban
tests/         тесты, включая сверку с алгоритмом Marzban
```

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполнить DATABASE_URL, SECRET_KEY, SUBSCRIPTION_*
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Таблицы создаются при первом старте. Тогда же заводится администратор из
`ADMIN_USERNAME` / `ADMIN_PASSWORD` — но только если в базе нет ни одного
админа.

На Railway: подключить репозиторий, добавить Postgres, задать переменные из
`.env.example`. `railway.json` и `Procfile` уже в репозитории.

## Переход с Marzban

Порядок важен: ссылки останутся живыми только если совпадут **домен, путь
и секрет подписи**.

**1. Поднять панель** рядом с работающим Marzban (на другом порту/домене).
В `.env` указать:

```
SUBSCRIPTION_BASE_URL=https://nexlovpn.online   # тот же домен, что был у Marzban
SUBSCRIPTION_PATH=c                             # тот же префикс пути
```

**2. Перенести базу.**

```bash
pip install -r requirements-migrate.txt

python scripts/migrate_from_marzban.py \
    --source "sqlite:////var/lib/marzban/db.sqlite3" \
    --xray-config /var/lib/marzban/xray_config.json \
    --dry-run          # сначала посмотреть, что переносится
```

Для MySQL-установки: `--source "mysql+pymysql://user:pass@127.0.0.1/marzban"`.

Скрипт напечатает `SUBSCRIPTION_SECRET=...` — это секрет из таблицы `jwt`
Marzban. **Его обязательно прописать в `.env` панели**: без него подписи
старых ссылок не сойдутся и подписки перестанут открываться.

Переносятся: администраторы (с хешами паролей), пользователи со статусами,
трафиком, лимитами и сроками, ключи (UUID/пароли), хосты ссылок, ноды
(выключенными) и inbound'ы. Скрипт идемпотентен — существующие записи он
пропускает, поэтому перед самым переключением его можно прогнать ещё раз,
чтобы догнать свежие оплаты.

**3. Заполнить недостающее в панели.** Параметры inbound'ов берутся из
`xray_config.json`, но `publicKey` для REALITY в серверном конфиге не
хранится — впишите его вручную (`xray x25519 -i <privateKey>` на сервере),
иначе клиенты не подключатся.

**4. Поставить агента на каждый сервер** (страница «Серверы» → «Добавить
сервер» → скопировать команду):

```bash
curl -fsSL https://panel.example.com/install/install_agent.sh -o install_agent.sh
AGENT_TOKEN=<токен из формы> PANEL_URL=https://panel.example.com bash install_agent.sh
```

Скрипт ставит Xray-core и агента, поднимает `systemd`-сервис `vpn-agent`.
**Порт агента (8443) закройте файрволом для всех, кроме адреса панели.**

**5. Проверить** на тестовом аккаунте: открыть его ссылку подписки, убедиться,
что отдаются конфиги и соединение работает.

**6. Переключить домен** подписок с Marzban на панель и погасить Marzban.
Пользователи ничего не замечают: ссылка та же.

## Интеграция с ботами

Ничего переписывать не нужно — в NexloVPN и TGAdminBot меняются только
переменные окружения:

```
MARZBAN_URL=https://panel.example.com
MARZBAN_USERNAME=<логин админа панели>
MARZBAN_PASSWORD=<пароль>
SUBSCRIPTION_BASE_URL=https://nexlovpn.online
```

Совместимые эндпоинты: `POST /api/admin/token`, `GET /api/inbounds`,
`POST /api/user`, `GET|PUT|DELETE /api/user/{username}`, `GET /api/users`,
`POST /api/user/{username}/reset`, `POST /api/user/{username}/revoke_sub`,
`GET /api/system`, `GET /api/sub?token=...` (последний использует AppVPN,
чтобы узнать актуальный адрес подписки).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest                                   # без базы: unit-тесты

TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/vpnpanel pytest
                                         # плюс сквозной тест API и веб-панели
```

`tests/test_subscription.py` сверяет генерацию токенов с эталонной
реализацией Marzban — именно этот тест гарантирует, что старые ссылки
останутся рабочими.

## Безопасность

- Порт агента должен быть доступен только панели: токен — единственная
  защита, TLS у агента опционален (`agent_tls` + `SSL_CERTFILE`/`SSL_KEYFILE`).
- `SECRET_KEY` и `SUBSCRIPTION_SECRET` не должны попадать в репозиторий.
- Пароль первого администратора смените после первого входа: он берётся
  из переменных окружения и создаётся только один раз.
- Приватные ключи REALITY хранятся в базе и уезжают на ноды; в клиентские
  ссылки попадает только публичный ключ.

## Что пока не сделано

- Клиентские форматы Clash и sing-box (сейчас — base64, plain и JSON;
  этого достаточно для v2rayNG, NekoBox, Hiddify и AppVPN).
- Автоматический сброс трафика по стратегиям `day`/`week`/`month`
  (поле хранится и переносится, но планировщика сброса ещё нет).
- Раздача ролей администраторам: все админы равноправны.
- Страница финансов — платежи живут в базе ботов, в панель пока не выведены.
