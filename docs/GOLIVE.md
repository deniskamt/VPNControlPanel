# Боевой запуск: тестовая панель становится основной

Инструкция для перехода, когда панель проверена на тестовом сервере и должна
занять место Marzban, а домен подписок меняется на `sub.nexlovpn.online`.

Всё написано под конкретный переезд: старый домен подписок —
`nexlovpn.online`, новый — `sub.nexlovpn.online`. Подставьте свои, если
отличаются.

---

## Три вещи, от которых зависит успех

Ссылка подписки выглядит так:

```
https://nexlovpn.online/c/dXNlcl8xLDE3NDU0NDU1NTM...
└──────── домен ───────┘└┬┘└──────── токен ───────┘
                        путь
```

Токен считается из имени пользователя, даты его создания и
`SUBSCRIPTION_SECRET`. Значит, у людей всё продолжит работать, только если
совпадают **все три**:

1. **секрет** — `SUBSCRIPTION_SECRET` в `.env` равен секрету из таблицы `jwt`
   базы Marzban (его печатает `scripts/migrate_from_marzban.py`);
2. **путь** — `SUBSCRIPTION_PATH=c`;
3. **домен** — тот, что стоит в уже выданных ссылках, то есть
   `nexlovpn.online`.

Первые два переезжают вместе с `.env`. А вот домен меняется — и это
единственное, что может тихо сломать людей. Клиент в телефоне ходит по той
ссылке, которую получил когда-то; про `sub.nexlovpn.online` он не знает.
Поэтому **старый домен должен продолжать отвечать** — как именно, разобрано
ниже в разделе «Старые ссылки».

`SUBSCRIPTION_BASE_URL=https://sub.nexlovpn.online` влияет только на ссылки,
которые панель показывает и отдаёт боту **после** переключения.

---

## Какой вариант выбрать

**Вариант А — панель остаётся на тестовом сервере, меняется только домен.**
Проще и безопаснее: панель уже работает, агенты настроены, база наполнена.
Переключается DNS, Marzban гасится. Откат = вернуть DNS обратно.

**Вариант Б — панель переезжает на сервер, где сейчас Marzban.** Нужен,
только если этот сервер жалко отдавать или к нему привязан IP в белых
списках. Тогда база и настройки переносятся архивом.

Дальше расписаны оба.

---

## Вариант А: переключить домен на тестовый сервер

### 1. Догнать свежие данные из Marzban

За время проверки в Marzban появились новые оплаты и пользователи. Скрипт
переноса идемпотентен — существующие записи он пропускает, поэтому его
запускают ещё раз прямо перед переключением.

На сервере Marzban:

```bash
cp /var/lib/marzban/db.sqlite3 /tmp/marzban-copy.sqlite3
scp /tmp/marzban-copy.sqlite3 root@<сервер панели>:/opt/vpn-panel/marzban.sqlite3
```

На сервере панели:

```bash
cd /opt/vpn-panel
.venv/bin/python scripts/migrate_from_marzban.py \
    --source "sqlite:////opt/vpn-panel/marzban.sqlite3"
```

Скрипт печатает, сколько всего пользователей в базе-источнике и сколько
перенёс. Числа должны сойтись — если перенеслось заметно меньше, значит
в команде остался `--limit`.

Копию базы после проверки удалите: в ней ключи всех пользователей.

```bash
rm -f /opt/vpn-panel/marzban.sqlite3
```

### 2. Направить домены на сервер панели

В DNS:

- `sub.nexlovpn.online` → A-запись на IP сервера панели;
- `nexlovpn.online` → туда же, **если** на нём не живёт сайт (иначе см.
  «Старые ссылки», способ 2).

Cloudflare: на время выпуска сертификата запись должна быть «DNS only»
(серое облако). Подождите, пока `getent ahostsv4 sub.nexlovpn.online`
покажет нужный адрес.

### 3. Выдать домен и сертификат

```bash
cd /opt/vpn-panel
bash scripts/setup_domain.sh sub.nexlovpn.online \
     --also nexlovpn.online \
     --email <ваша почта>
```

`--also` добавляет домен в `server_name` nginx и в сертификат: панель начнёт
отвечать и по старому адресу, поэтому выданные ранее ссылки продолжат
открываться. Ключ можно повторять для нескольких доменов.

Скрипт сам пропишет в `.env`:

```
PANEL_URL=https://sub.nexlovpn.online
SUBSCRIPTION_BASE_URL=https://sub.nexlovpn.online
```

Если порт 443 на этом сервере занят подключением Xray, скрипт остановится и
ничего не изменит — это тот самый конфликт «панель против VPN». Разведите их
по разным серверам или перенесите подключение на другой порт.

### 4. Перенастроить бота

Бот ходит в Marzban по REST API, и панель этот API повторяет — менять код не
нужно, только адрес. В `.env` бота:

```
MARZBAN_URL=https://sub.nexlovpn.online
SUBSCRIPTION_BASE_URL=https://sub.nexlovpn.online
MARZBAN_USERNAME=<логин админа в панели>
MARZBAN_PASSWORD=<пароль админа в панели>
```

Порт `:8443` из старого адреса убирается — панель за nginx на 443.
Администратор в панели тот же, что был в Marzban: хеши паролей перенеслись.

Что бот использует и что панель отдаёт: `POST /api/admin/token`,
`GET /api/inbounds`, `POST /api/user`, `GET /api/user/{username}`,
`PUT /api/user/{username}`. Все на месте.

После правки — `systemctl restart <сервис бота>` и создать тестового
пользователя из бота: он должен появиться в панели.

### 5. Погасить Marzban

Только после того, как проверки из чек-листа прошли.

```bash
# на сервере Marzban — сначала полный снимок, его не удалять пару недель
tar -czf /root/marzban-backup-$(date +%F).tar.gz /var/lib/marzban /opt/marzban

marzban down                    # остановить
systemctl disable marzban 2>/dev/null || true
```

Удалять данные Marzban сразу не нужно: пока лежат — есть куда вернуться.

## Вариант Б: перенести панель на другой сервер

### 1. Снять архив на тестовом сервере

```bash
cd /opt/vpn-panel
bash scripts/backup_panel.sh
```

Получится `/root/vpn-panel-<хост>-<дата>.tar.gz`: полный дамп базы плюс
`.env` с ключами. Скрипт печатает, сколько внутри пользователей и серверов —
сверьте с панелью.

### 2. Освободить и подготовить боевой сервер

Marzban держит 443/8443 — панель туда не встанет, пока он работает.

```bash
tar -czf /root/marzban-backup-$(date +%F).tar.gz /var/lib/marzban /opt/marzban
marzban down
```

Поставить панель начисто:

```bash
apt update && apt install -y git
git clone https://github.com/deniskamt/VPNControlPanel.git /opt/vpn-panel
cd /opt/vpn-panel
bash scripts/install_panel.sh
```

На вопросы можно отвечать чем угодно: адреса и ключи всё равно приедут из
архива на следующем шаге.

### 3. Развернуть архив

```bash
scp /root/vpn-panel-*.tar.gz root@<боевой сервер>:/root/     # с тестового

# на боевом
cd /opt/vpn-panel
bash scripts/restore_panel.sh /root/vpn-panel-<...>.tar.gz
```

Что делает `restore_panel.sh`:

- снимает страховочный дамп текущей базы в `/root/vpn-panel-before-restore-*.sql.gz`;
- заменяет базу содержимым архива;
- переносит настройки из архивного `.env`, включая `SECRET_KEY` и
  `SUBSCRIPTION_SECRET` — без них старые ссылки не откроются;
- оставляет от этого сервера `DATABASE_URL`, `PANEL_URL` и
  `SUBSCRIPTION_BASE_URL` — адреса задаются следующим шагом.

### 4. Домен, бот, Marzban

Дальше — шаги 2–5 варианта А: DNS, `setup_domain.sh` с `--also`,
`.env` бота, остановка Marzban.

### 5. Агенты на нодах

Панель сама стучится к агентам, поэтому смена её адреса нодам безразлична —
кроме одного случая: если на ноде порт агента закрыт файрволом по адресу
прежней панели. Тогда на каждой ноде:

```bash
ufw allow from <IP новой панели> to any port 8443 proto tcp
ufw delete allow from <IP старой панели> to any port 8443 proto tcp
```

Порт агента смотрите в панели, в карточке сервера.

Команда установки агента печатается в панели с новым `PANEL_URL`, поэтому
переставлять агентов не нужно — только если будете обновлять.

## Старые ссылки: как их не потерять

Все ссылки, выданные до переезда, ведут на `nexlovpn.online`. Способы:

**1. Домен целиком уезжает на панель.** A-запись `nexlovpn.online` на сервер
панели, `setup_domain.sh ... --also nexlovpn.online`. Самый простой путь,
годится, если на этом домене нет сайта.

**2. На `nexlovpn.online` остаётся сайт.** Тогда сайт отдаёт подписки сам,
проксируя только путь `/c/`. В его nginx, внутри `server` с
`server_name nexlovpn.online`:

```nginx
location /c/ {
    proxy_pass https://sub.nexlovpn.online;
    proxy_set_header Host sub.nexlovpn.online;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_ssl_server_name on;
}
```

Проверить: `nginx -t && systemctl reload nginx`, затем открыть любую старую
ссылку — должен прийти тот же ответ, что и с нового домена.

**3. Ничего не делать.** Все выданные ссылки перестают открываться в один
момент. Допустимо, только если бот заранее разошлёт новые всем и вы готовы к
потоку обращений. Не рекомендуется.

Держать старый домен рабочим стоит долго — месяцами. Ссылку в клиенте люди
не меняют, пока она работает.

## Чек-лист переключения

Проверять по порядку, каждый пункт — до того, как гасить Marzban.

```bash
# 1. Панель отвечает по новому домену
curl -sS -o /dev/null -w '%{http_code}\n' https://sub.nexlovpn.online/healthz     # 200

# 2. Сертификат покрывает оба домена
certbot certificates | grep -A1 Domains

# 3. Старая ссылка реального пользователя (взять из Marzban) открывается
curl -sS -o /dev/null -w '%{http_code}\n' https://nexlovpn.online/c/<токен>       # 200

# 4. Она же на новом домене
curl -sS -o /dev/null -w '%{http_code}\n' https://sub.nexlovpn.online/c/<токен>   # 200
```

5. Подключиться с телефона по **старой** ссылке из HAPP — трафик идёт.
6. В панели «Серверы» — все зелёные, время последнего опроса свежее.
7. В панели «Подписка» — выбрать пользователя и посмотреть, что попадёт в
   его подписку и что не попало (там же написано, почему).
8. В боте создать тестового пользователя — он появляется в «Пользователях»,
   ссылка из бота открывается.
9. Счётчики трафика растут: «Пользователи» → любой активный.

## Откат

Пока Marzban не удалён, вернуться можно за минуты.

- **Вариант А:** вернуть A-запись `nexlovpn.online` на сервер Marzban,
  поднять его: `marzban up`. Панель никуда не денется, ссылки снова
  обслуживает Marzban.
- **Вариант Б:** там же плюс восстановить базу панели из страховочного
  дампа:

  ```bash
  gunzip -c /root/vpn-panel-before-restore-<дата>.sql.gz \
    | psql "postgresql://vpnpanel:<пароль>@127.0.0.1:5432/vpnpanel"
  ```

Данные, накопленные панелью после переключения (трафик, новые
пользователи), при откате на Marzban теряются — поэтому чек-лист лучше
пройти до, а не после.

---

## Безопасность

- Архив `backup_panel.sh` и копия базы Marzban — это ключи всех
  пользователей и секрет подписи подписок. Разложили — удалите:
  `shred -u /root/vpn-panel-*.tar.gz /opt/vpn-panel/marzban.sqlite3`.
- `.env` держите с правами `600` (скрипты так и делают).
- Домен тестовой панели после переезда лучше отключить совсем: если он
  останется рабочим со старой базой, часть клиентов может ходить за
  подписками туда.
- `SUBSCRIPTION_SECRET` и `SECRET_KEY` никуда не выкладывайте и не меняйте
  после запуска — смена первого мгновенно ломает все выданные ссылки.
